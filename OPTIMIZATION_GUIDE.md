# Руководство по оптимизации видеостабилизатора для Banana Pi CM4

## Быстрый старт

Для Banana Pi CM4 с Amlogic A311D используется автоматическая NEON оптимизация warpAffine().

```bash
cd /путь/к/проекту
mkdir -p build
cd build
cmake ..
make -j4
./myapp_opencl
```

## Настройка производительности

### 1. Размер плитки (TILE_SIZE)

Отредактируйте `src/warpAffine_neon_optimized.hpp`:

```cpp
static constexpr int TILE_SIZE = 64;  // Текущее значение
```

**Рекомендации:**
- `32` - если требуется максимальная параллелизация (4+ ядра)
- `64` - оптимум для Banana Pi (4 ядра, 1.8 GHz)
- `128` - если процессор мощнее или нужна минимизация overhead

После изменения пересоберите:
```bash
make clean && make -j4
```

### 2. Минимальный размер для NEON

По умолчанию NEON используется только для кадров >= 256x256. Для меньших разрешений используется стандартная warpAffine():

```cpp
if (dsize.width < 256 || dsize.height < 256) {
    cv::warpAffine(src, dst, M, dsize, ...);  // Стандартная версия
}
```

Если вы уверены, что работаете с большими кадрами:
```cpp
if (dsize.width < 128 || dsize.height < 128) {  // Более агрессивно
```

### 3. Количество потоков OpenMP

По умолчанию используется 4 потока (на все ядра ARM Cortex-A53):

```cpp
#pragma omp parallel for ... num_threads(4)
```

Если система имеет больше ядер:
```cpp
#pragma omp parallel for ... num_threads(8)  // Для 8-ядерного процессора
```

## Мониторинг производительности

### Проверка использования ядер

```bash
# В реальном времени
top -p $(pgrep myapp_opencl)
```

Должны быть задействованы все 4 ядра (примерно одинаковая нагрузка).

### Проверка частоты процессора

```bash
watch -n 1 "cat /proc/cpuinfo | grep MHz"
```

Если частота низкая (< 1.8 GHz), возможно включен CPU frequency scaling:

```bash
# Отключить scaling (требует root)
echo performance | sudo tee /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
```

### Мониторинг температуры

```bash
watch -n 1 "cat /sys/class/thermal/thermal_zone0/temp"
```

Нормальная температура: 40-60°C
Критическая: > 80°C (Banana Pi может начать дросселировать)

## Отключение NEON для отладки

Если нужна стандартная warpAffine для сравнения:

```cpp
const bool USE_NEON_WARP_AFFINE = false;  // Отключить NEON
```

Пересоберите и сравните производительность:
```bash
make clean && make -j4
```

## Память и система охлаждения

### Рекомендуемые улучшения аппаратного обеспечения

1. **Радиатор на SoC** - обязателен для стабильной работы
2. **Вентилятор** - желателен для длительных сеансов
3. **Дополнительная память** - Banana Pi имеет 2 ГБ ОЗУ, может быть недостаточно

### Проверка доступной памяти

```bash
free -h
```

Должно быть минимум 512 МБ свободной памяти для видеостабилизации.

## Интеграция с другими компонентами

### Если используется в production

1. **Логирование** - добавить в `main()`:
   ```cpp
   ofstream logFile("stabilizer.log", ios::app);
   // ... логирование в logFile
   ```

2. **Мониторинг ошибок** - обернуть `warpAffineOptimized()` в try-catch
3. **Graceful shutdown** - обработать сигналы (SIGINT, SIGTERM)

## Сравнение с другими методами

### FP16 GPU (старый метод)

**Плюсы:**
- Теоретически выше производительность
- Использует GPU

**Минусы:**
- Нестабильный (зависит от драйверов)
- Требует копирований GPU/CPU
- Проблемы синхронизации

### NEON CPU (текущий метод)

**Плюсы:**
- ✅ Стабильный
- ✅ Локальная память (кэш)
- ✅ Предсказуемая производительность
- ✅ FP32 качество

**Минусы:**
- Требует 4 ядра CPU
- Может быть горячее чем GPU (без теплоотвода)

## Troubleshooting

### Низкий FPS

1. Проверьте разрешение - уменьшите до 1280x720
2. Проверьте использование ядер - `top`
3. Проверьте температуру - возможно дросселирование
4. Проверьте исходный видеопоток - может быть медленным

### Нестабильная работа

1. Убедитесь, что используется NEON (`const bool USE_NEON_WARP_AFFINE = true`)
2. Включите режим отладки - добавить логирование в warpAffineOptimized()
3. Проверьте версию OpenCV (требуется 4.x)

### Артефакты в видео

1. Попробуйте INTER_NEAREST вместо INTER_LINEAR (более быстро, но хуже качество)
2. Увеличьте TILE_SIZE до 128
3. Проверьте исходное видео - может быть искажено
